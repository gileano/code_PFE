PROJECT OBJECTIVE AND RESEARCH ROADMAP
=====================================================================
OBJECTIVE: make quantum circuit optimization scale to larger circuits than
standard methods allow: split a target circuit into qubit blocks, use a
multi-objective GA to evolve a cheaper/shallower circuit per block that still
reproduces the original's behavior with high fidelity, then reassemble.
Matters for near-term (noisy, limited-connectivity) devices, where shallower
accurate circuits are hard to get via standard, non-partitioned optimization.
Timeline: ~4 months, laptop-only, targeting a December 2026 empirical results
paper submission (started 2026-08-18).

A separate survey/critical-analysis paper ("State-of-the-art and critical
analysis of Quantum-Inspired Evolutionary Algorithms for multi-objective
optimization: Taxonomy, Features, and Limitations", see journal.txt) is also
in progress, using this pipeline's results as an illustrative case study, not
as that paper's primary evidence. The two papers are separate deliverables.

CURRENT STATUS OF RESULTS (as of 2026-09-06) — READ THIS FIRST
=====================================================================
CRITICAL CAVEAT: two real bugs in the injection stage were found and fixed
2026-09-04 (commit e766aecf): (a) stochastic_injection/sa_injection/
fidelity_driven_injection all hardcoded candidate gates to blocks[0]/
blocks[1] only, ignoring every other block pair (partitions above ~n=8
routinely have >2 blocks); (b) extract_interblock_gates miscounted
weak_random's full-width barrier() calls as inter-block gates (barriers
touch all qubits, so trivially "span" every block -- one checked instance
had all 20 reported "inter-block gates" turn out to be barriers, true count
0). Impact was confirmed large and circuit/seed-dependent (+526%
fidelity_final on one n=8 seed, negligible on others). Every quantitative
finding dated before 2026-09-04 anywhere in this file's history is
SUPERSEDED -- do not cite old numbers without re-deriving them on the fixed
code (fix applied in final_m1_script.py: extract_interblock_gates skips
barriers; a new _rand_two_blocks(blocks, rng) helper replaces the
blocks[0]/blocks[1] hardcoding everywhere it appeared. This also changes RNG
stream consumption, so old runs aren't bit-reproducible against the new
code even for 2-block partitions).

VERIFIED POST-FIX (225-run core baseline: nsga2/nsga3/smsemoa x 5 circuits x
each family's own ceiling size x 5 seeds, point mutation, no hybrid-LAS,
stochastic injection; results_master.csv, 225 rows; pytest 19/19 passing):
- fidelity_final ranking: nsga2 highest in most circuit x size cells,
  mirroring the pre-fix ranking's general shape, but absolute numbers and
  the nsga3-vs-smsemoa runner-up order are not directly comparable to any
  pre-fix table.
- fidelity_driven_injection's greedy-pass win rate, previously reported as
  non-monotonic in n (dip at n=12, recovery at n=16), does NOT reproduce
  post-fix -- that dip-and-recover shape was itself an artifact of the two
  bugs. Post-fix it looks roughly monotonically increasing with n (24-40% @
  n=8, 8-28% @ n=12, 65-100% @ each family's own ceiling), though only
  confirmed on an uneven per-family size grid so far (not a matched uniform
  n=16 across all 5 families).
- Root cause of why n=8 moved as much as n=12 post-fix: qft/weak_random
  already averaged 4.0 blocks at n=8 (the bug was already live there, not
  only "above ~n=8" as first assumed); the other 3 families average ~2
  blocks at n=8 but still shifted, due to the fix's RNG-stream side effect.

SCALING (fidelity-estimation performance -- still current, independent of
the injection-stage bug fix above)
=====================================================================
Two-tier fidelity computation: exact (dense Operator trace, n <=
fidelity_exact_threshold, default 13) and approximate (Monte-Carlo above
it). Current approximate-tier backends: "echo_test_mc" (default, an
algebraically-equivalent replacement for an earlier SWAP-test estimator --
same quantity, computed on n qubits instead of 2n+1, no CSWAP-induced
entanglement -- ~1000x+ faster for entangled circuits) and
"statevector_mc" (opt-in per circuit family, exact per-sample/no shot
noise, much faster for highly-entangled families but much slower than echo
for low-entanglement ones -- no auto-selection, pick per family).

fidelity_driven_injection's per-trial loop has its own fast paths: exact
below injection_fidelity_exact_threshold (lowered 12->7, since statevector
already wins by n=8 and the gap grows exponentially with n), a statevector
fast path up to statevector_fast_path_threshold (default 24), each trial
computed exactly via cached/incrementally-updated state vectors.
injection_fidelity_samples raised 2->8 (better tracks the exact tier's
accept/reject decisions at n=12/13, ~100-700x cheaper than exact).

Per-family qubit ceilings (validated by real pilot reruns, wired into
run_sweep.py's CIRCUIT_FIDELITY_SETTINGS, applied only above
fidelity_exact_threshold): weak_random reaches n=20 at plain defaults;
w_state and hw_efficient_ansatz reach n=20 with raised echo samples/shots
(8->32 samples, 128->2048 shots -- a resolution fix, not a speed one);
qaoa_maxcut (ceiling n=16) and qft (reaches n=20) need the statevector
backend (speed, and for qaoa_maxcut also resolution). qaoa_maxcut becomes
memory-bound under statevector past ~n=24-28 regardless of entanglement --
not a software limit to chase further; classical-shadow/tensor-network
fidelity estimation (arXiv 2209.02093) would be the real next step there.
Current run_sweep.py grid: weak_random/w_state/qft/hw_efficient_ansatz =
[8,12,20], qaoa_maxcut = [8,12,16].

Not done / open: sa_injection and stochastic_injection accept
injection_fidelity_exact_threshold as a kwarg but, per code inspection
(not verified empirically), never reach the branch it gates in real use --
only fidelity_driven_injection is affected by that threshold in practice.
louvain_partition has no seed of its own -- reproducible only because
run_experiment.py/run_sweep.py seed global random/np.random first; a direct
caller of the pipeline functions would need to replicate that.

HYPERVOLUME COMPARABILITY ACROSS ALGORITHMS (methodology finding, still
current)
=====================================================================
evaluate_run's hypervolume uses a PER-RUN ADAPTIVE reference point/
normalization (derived from that run's own final population) -- fine for
tracking one run's own convergence, but not valid for ranking different
algorithms/runs against each other, since the same absolute HV value means
something different per run. Fixed by adding front_raw (the Pareto front in
natural, unnormalized units) to evaluate_run's output, and a fair
(shared-reference) hypervolume table in generate_report.py that pools all
algorithms' front points per block, derives one shared min/max
normalization, and evaluates HV against one shared fixed reference point.
On the pre-fix dataset this flipped the nsga2-vs-smsemoa ranking entirely
and shrank (but didn't erase) the nsga2-vs-nsga3 gap -- exact numbers not
repeated here since they're pre-injection-fix data; the METHODOLOGICAL
point (always use fair HV for cross-algorithm comparison, adaptive HV only
for single-run convergence plots) is what's still load-bearing.
Also verified as a genuine structural property, independent of any data:
hybrid_las structurally cannot affect the recorded Pareto front (front_raw
is computed on `pop` before hybrid_las runs; hybrid_las only refines a copy
of the winning individual afterward) -- so fair/adaptive HV are always
identical between hybrid_las on/off, by construction, at any n.

Not done / open: no investigation of WHY nsga3's front is genuinely smaller
under a fair comparison (e.g. Das & Dennis niching vs. NSGA-II's crowding
distance) -- open if it matters for the paper.

CANDIDATE PIPELINE EXTENSIONS FROM RELATED WORK (web research, 2026-08-18
and 2026-08-27; not yet done unless noted)
=====================================================================
- Hyperedge-aware partitioning (hypergraph gate model + METIS block-count
  sweep instead of fixed-modularity Louvain) -- arXiv 2506.09963.
- Classical-shadow / tensor-network fidelity estimation for scale beyond
  what the echo/statevector backends cover -- arXiv 2209.02093.
- RL + ZX-calculus as a compression-stage alternative to compress_custom's
  hand-rolled passes (scales to 80q, PyZX/Qiskit integration exists) --
  arXiv 2312.11597. Biggest potential compression win, but an external
  RL+ZX dependency chain -- treat as a stretch goal.
- Noise/crosstalk-aware objective (could become a 4th NSGA-II objective, or
  extend _sa_energy's existing crosstalk-term placeholder) -- arXiv
  2207.05751, arXiv 2505.09036 -- plus noise-weighted partition cuts
  (DisMap/FitCut-style) as a complementary idea. Needs a noise model, which
  the project doesn't have yet.
- Wider Pareto-dominance MOO lineage reviewed (VEGA->MOGA->NPGA->SPEA->
  PAES->PESA->PESA-II->SPEA2->weak constraint-Pareto dominance, 2026-08-27,
  full detail in moo.txt): no change to the priority order above. PAES
  (a (1+1) evolution strategy, no population/crossover) doesn't fit this
  project's population-parallel/joblib design -- not prioritized, but worth
  naming as evidence the population-GA design was a deliberate choice. Weak
  constraint-Pareto dominance doesn't apply (all 3 objectives here are
  soft, not hard constraints).
- Mutation-operator ablation (arXiv 2504.06413) and pure-GA-vs-hybrid-GA+LAS
  (arXiv 2504.17561) -- DONE, pre-fix (see CURRENT STATUS above for the
  supersession caveat).
